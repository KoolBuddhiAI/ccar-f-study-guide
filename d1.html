1.1 The agentic loop — the one thing to know cold

What it means. An agentic loop is: send a request → Claude responds → inspect stop_reason. If it's tool_use, execute the requested tool, append the result to the conversation history, and send the next request. If it's end_turn, the task is done. The model decides what to call next based on accumulated context — that's what makes it an agent rather than a pre-scripted chain.

  • Model-driven vs preconfigured: Claude choosing tools from context beats fixed decision trees or tool sequences. The exam tests that you know the difference.
  • Tested anti-patterns: scanning assistant text for "done"/"task complete" as a stop signal; setting an arbitrary iteration cap as the primary stopping mechanism; ending the loop on any tool error; checking for assistant text content as a completion indicator.
  • Tool results must land in the history between iterations — otherwise the model can't incorporate new information.
In this repo: the session that built this guide ran the loop live — search → read → fetch → write, each result appended before the next decision, stopping only on final text. The transcript is the specimen.

1.2 Coordinator–subagent (hub-and-spoke)

What it means. One coordinator agent owns everything: decomposing the task, spawning subagents, routing all information between them, handling their errors, and aggregating results. Subagents never talk to each other directly — spokes through the hub, for observability and consistent error handling.

  • Dynamic selection: a good coordinator analyzes the query and invokes only the subagents it needs — not always the full pipeline.
  • Partition to avoid duplication: assign each subagent distinct subtopics or source types.
  • Over-decomposition trap: slicing the task too narrowly leaves broad research topics under-covered.
  • Iterative refinement: the coordinator evaluates the synthesis for gaps, re-delegates with targeted queries, and re-runs synthesis until coverage is sufficient.

1.3 Subagent invocation, context passing, spawning

What it means. Subagents start blank. They don't inherit the coordinator's conversation, and there's no shared memory between invocations — everything they need must be in the prompt you spawn them with.

  • The Task tool spawns subagents; the coordinator's allowedTools must include "Task" or it can't delegate at all.
  • Pass complete prior findings in the prompt — e.g., web-search results and document analysis handed to the synthesis subagent.
  • Use structured formats that separate content from metadata (source URLs, doc names, page numbers) to preserve attribution between agents.
  • Parallelism: emit multiple Task calls in one coordinator response, not spread across turns.
  • Write coordinator prompts as goals + quality criteria, not step-by-step procedures — it lets subagents adapt.
  • AgentDefinition config covers each subagent type's description, system prompt, and tool restrictions; fork-based sessions explore divergent approaches from a shared baseline.
In this repo: the agent's sessions_spawn is this exact API — context="isolated" starts clean, context="fork" copies the transcript, and the task must be fully self-contained either way. The child sees nothing implicit.

1.4 Enforcement & handoff patterns

What it means. When ordering must happen (identity verified before a refund), enforce it in code — prerequisite gates and hooks. Prompt instructions alone have a non-zero failure rate; deterministic compliance needs deterministic mechanisms.

  • Programmatic gate example: block process_refund until get_customer has returned a verified customer ID.
  • Structured handoffs: when escalating to a human who can't see the transcript, compile a summary — customer ID, root cause, amounts, recommended action. Free-text "please help" loses the case.
  • Multi-concern requests: decompose into distinct items, investigate in parallel with shared context, synthesize one resolution.
In this repo: digest.py gates its pipeline in code: check_quota() (l.93) blocks before any API spend, and the sent_video_ids ledger makes re-delivery structurally impossible. The recovery skill §3a demands three preconditions before a force-run — gate first, act second.

1.5 Agent SDK hooks — interception & normalization

What it means. The Agent SDK exposes hook points around the tool lifecycle — e.g., PostToolUse — where your code can intercept a tool call, inspect it, and normalize the data before it re-enters the model's context (trim it, reformat it, redact it).

  • Know the pattern names: hooks intercept; normalization reshapes tool output into the form the model consumes best.
  • This is the programmatic counterpart to 1.4 — enforcement implemented at the SDK layer rather than hoped for in prompts.
Domain takeaway: the loop terminates on stop_reason, never on words or counters. Subagents are blank slates — the coordinator's real job is packaging context. Deterministic requirements get code, not prose.
